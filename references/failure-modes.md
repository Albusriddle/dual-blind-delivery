# 失败模式库

> 每条都来自真实交付（本 skill 的诞生现场：操作系统五讲课堂练习刷题页，34 题 / 146 小问 / 双盲两套 / 三人四轮）。
> 格式：**现象 → 根因 → 检出手段 → 对策**。这里的每一条都能写成断言，请把能自动化的都塞进 `validate.mjs`。

---

## F1 位置偏置：正确答案永远在第一个

- **现象**：73 个选择题里，**100%** 的正确选项在下标 0（A 侧 46/46、B 侧 36/36）。多选的正确集合也全部包含下标 0。
- **根因**：作者按"正确答案先写、干扰项后补"的顺序起草，从不回头打乱。
- **代价**：刷题页退化成"永远选 A"的肌肉记忆训练；作为自测工具的可信度归零。
- **检出**：统计正确项下标分布；单一位置占比 > 60% 报警。
  ```js
  const d = {}; asks.filter(a => a.t === 'mcq').forEach(a => d[a.ans] = (d[a.ans] || 0) + 1);
  // 报警条件：max(d.values()) / total > 0.6
  ```
- **对策**：构建期做**确定性重排**（固定种子，可复现），并同步重映射答案下标。
  - 按"选项数"分层轮转定目标位，避免随机导致的二次偏置
  - 纯数值选项改为**按值升序**（重排会让数字跳序，反而降低可读性）

## F2 重排的连带伤害：解析里的指代错位

- **现象**：正确答案换位置后，解析里写着"选项 C 把总运行时间当剩余时间"——C 已经是别的选项了。
- **根因**：解析用**位置指代**（字母/序号）描述内容，重排只改了 `opts` 与 `ans`，没改文本。
- **检出**：重排前后，对每个指代做"所指选项文本是否相同"的断言。
  ```
  旧「选项 C」→ 选项文本 T ；新「选项 X」→ 选项文本 T' ；断言 T == T'
  ```
- **对策**：
  1. 重排时**同时重映射**字母（`选项 X`）与序号（`第 N 项`）；
  2. **禁止**对整段解析做全局字母替换——调度题里 A/B/C/D 是作业名，页面置换题里是页名，一替换就全毁；
  3. 更稳的写法是**按内容指代**（"用总运行时间比较的那一项"），从源头消灭位置依赖。

> 本次实战第一层：30 处「选项 X」；改完发现第二层：12 处「第 N 项」；第三层：一句「前 3 项都能打破…」依赖顺序，重排后语义直接崩坏，只能改写。**一次重排触发三轮返工。**

## F3 真值偏斜：判断题清一色是"错"

- **现象**：28 条判断题里 24 条为假（86%）。一律答"错误"就能拿高分。
- **根因**：作者用"把常见误解写成命题"的方式来出判断题——而误解天然是假命题。
- **检出**：`true:false` 比例；偏离 1:1 超过 3:1 报警。
- **对策**：成对设计——每条误解命题配一条"改成正确表述"的命题；或构建期把部分假命题改写成等价真命题（保留同一考点，换表述方向）。
- **注意**：改写必须**同步重写解析**，否则解析在解释一个不存在的错误。

## F4 参考答案本身就有问题

- **现象**：源 PDF 的参考答案里，
  - 一处时间线漏标了中途降级（结论不变但考点缺失）；
  - 一处把"段号 11"（二进制）写成十进制读法会自相矛盾；
  - 一处把"读取 4 字"按"4 字节"作答；
  - 一处延伸公式给了错误系数。
- **根因**：讲义参考解答是"讲评用"的，允许省略与近似。
- **检出**：复核员**独立复算**（离散事件模拟、逐 tick 推演），与参考答案比对。
- **对策**：
  1. 复核员的 KEY 必须设「源材料存疑项」一节；
  2. 在 REVIEW 里区分"A 复述了含混答案"与"B 答错了"——严重度差一级；
  3. 生产者被要求"若源材料有误，按正确推导写并记录"。

## F5 判分粒度错配：整卡判分

- **现象**：一题 5 个小问，对 4 个错 1 个，整题记错；正确率按题统计，反馈不到小问级。
- **根因**：实现时图省事，`submit()` 里 `r.ok = allOk`。
- **检出**：读码 + 手动"只错一个再提交"。
- **对策**：按小问记录 `{done, ok}`，卡片级只做汇总；错题本精确到"错在第几问"。

## F6 跨产物状态污染

- **现象**：A、B 两个页面在 `file://` 下共享 `localStorage`，打开 A 做过题，B 一打开就显示 A 的进度。
- **根因**：`file://` 在同一个浏览器里被视为同一源；两套产物用了同一个存储键。
- **检出**：先打开产物 1 → 再打开产物 2 → 看进度是否继承。
- **对策**：测试流程里"测下一套前先清存储"；交付物与测试物用不同键或不同版本号。

---

## F7 交付的是旧字节

- **现象**：`final/index.html` 已是最新，用户目录下的副本还是上一版。
- **根因**：改了构建、忘了复制；或复制了但没校验。
- **检出**：`sha256(构建产物) vs sha256(交付副本)`。
- **对策**：复制与校验写成一条命令；哈希写进 `MERGE_NOTES.md`；二审报告开头必须写被审对象的哈希。

---

## F8 审核后的"小改动"绕过复核

- **现象**：二审通过后，Lead 顺手改了 5 处（排序、文案、跳转、解析），没有再复核。
- **根因**："就改了几个字"的心理账户。
- **代价**：那 5 处里真的有一处把选项顺序改成了非升序，还有一处跳转没生效。
- **检防**：`ROUNDS.md` 强制记录；二审人按**哈希差集**确定 Δ 范围。
- **对策**：任何审核后改动 → 必走一轮 Δ 复核（可轻量，但必须逐项断言）。

---

## F9 隔离失效：两个"独立"作者其实看过同一份草稿

- **现象**：两套产物措辞高度雷同，差异只在外观。
- **根因**：Lead 在派工前给其中一方看过另一方的草图；或两者共用了一个中间文件。
- **检出**：抽 5 条对方高频短语反向检索（`scripts/blindness.mjs`）；比对两侧独有词汇表。
- **对策**：目录隔离 + 提示词逐字相同 + 中间产物不共享。

---

## F10 报告变成"好评"

- **现象**：复核结论"两套都很好，建议合并优点"。
- **根因**：没有评分口径、没有逐项判决、没有严重度定义。
- **检出**：数一数报告里"通过/不通过"的格子数是否等于 `条目数 × 2`。
- **对策**：强制三件套——评分卡（先定口径）、逐项判决表（每格有证据）、逐项取谁表（可直接执行）。

---

## F11 门禁形同虚设

- **现象**：`validate` 永远 0 error。
- **根因**：校验器写成了"文件存在性检查"；或在实现过程中被一路放宽到能过。
- **检出**：**空跑**——对空目录/删掉一个必填字段跑一次，必须报错。
- **对策**：G0 把"空跑报错"列为门禁项；校验器只允许 Lead 改，改一次记一条。

---

## F12 返工只验失败项

- **现象**：修完 blocker，只重跑了那条断言，其他不动——结果修复引入两类新错。
- **根因**：把"修复"当成局部操作。
- **检出**：看不到（只有复跑整个门禁才能看到）。
- **对策**：**整门禁复跑**写进返工规则；每轮 `ROUNDS.md` 记一行。

## 附：缺陷类型 → 机械检测速查

| 类型 | 一行断言 | 适用 |
|---|---|---|
| 位置偏置 | 正确项下标分布熵 | 选择题 |
| 真值偏斜 | 布尔比例 | 判断题 |
| 引用漂移 | 指代文本前后一致 | 重排/重编号后 |
| 计数不一致 | 占位符数 == 答案数组长度 | 填空/模板 |
| 自包含 | 无 `http(s)://`、无 `src=`、无 `fetch(` | 单文件交付 |
| 副本一致 | sha256 相等 | 所有交付 |
| 状态污染 | 两产物不共享存储键 | 多产物 |
| 隔离性 | 无对方路径/措辞 | 双盲 |
| 结构完整 | id 全集覆盖 + 必填字段 | 所有 |
| 门禁有效性 | 空输入必须报错 | 校验器自身 |
