# 提示词模板

> 用法：把 `{{...}}` 替换成实际值。**两个生产者的提示词必须逐字相同**，只允许替换 `{{DIR}}`、`{{SIDE}}`、`{{TASK_ID}}`。

---

## 0. 生产者（A / B）— 双盲主体

```text
你是「{{SIDE}} 方案」的生产者。环境：{{ENV}}。

# 任务
严格按施工合同 {{WORK}}/contract/SPEC.md，独立完成 {{DELIVERABLE}}，写入 {{WORK}}/{{DIR}}/。

# 流程
1. 领取任务：{{TASK_ID}}（如使用共享任务板：先 get → claim）。
2. 通读合同（数据结构、内容规范、验收、禁则）。
3. 读源材料：{{SOURCE}}。
4. 只写 {{WORK}}/{{DIR}}/。**绝对不要读 {{WORK}}/{{OTHER_DIR}}/**，不要改 contract/ 与源材料。
5. 建构建脚本，做到"一键重产出"（{{BUILD_CMD}}）。
6. 自检：{{VALIDATE_CMD}} 必须 0 error，反复修到全绿。
7. 交互/人工自测（若产物可交互）：至少验证 {{SELF_TEST_ITEMS}}；结果写进 NOTES.md。
8. 完成并汇报。

# 质量红线
{{QUALITY_BARS}}

# 交付
- {{WORK}}/{{DIR}}/{{DELIVERABLE}}
- {{WORK}}/{{DIR}}/NOTES.md：构建命令、validate 输出、自测记录、**主动列出你已知的不足（至少 1 条）**、你修正过的源材料问题

# 汇报口径
一条不超过 10 行的消息：条目数 / 体积 / validate 结果 / 你修了什么 / 已知不足。
全程自主推进，非致命问题自行决策；不要为确认而停下来。
```

**填写要点**

| 占位 | 说明 |
|---|---|
| `{{QUALITY_BARS}}` | 用**可判真假**的句子：条目数下限、必须覆盖的小问数、必含结构、禁用写法（给 3–8 条） |
| `{{SELF_TEST_ITEMS}}` | 针对产物的关键行为清单（如"刷新后状态恢复""窄屏无横向滚动"） |
| `{{ENV}}` | 可用的工具与版本（bash / node / python / 浏览器） |

> 实测有效的一句：**"主动列出你已知的不足"**。作者最清楚哪里偷懒，这句话能在复核前拿到最有价值的信息。

## 1. 复核员 · 阶段一（写基线，不许看 A/B）

```text
你是独立第三方复核员。环境：{{ENV}}。

# 阶段一（现在只做这个）
1. 领取任务：{{AUDIT_TASK_ID}}。
2. **只读**源材料 {{SOURCE}} 与合同 {{WORK}}/contract/SPEC.md。
   **不要打开 {{WORK}}/{{DIR_A}}/ 与 {{WORK}}/{{DIR_B}}/ 的任何文件**——保持独立。
   （Lead 已把这两个目录移到 {{WORK}}/_sealed/；如果它们还可见，说明隔离流程没执行，请先告知我。）
3. 逐条（共 {{N_ITEMS}} 条）独立推导，写 {{WORK}}/audit/KEY.md，**格式严格按 {{WORK}}/contract/KEY_SPEC.md**：
   - 每条：id、核心条件（数字）、关键中间量、最终结论、≥2 条易错点
   - 文件头写**独立性声明**（三选一：时间戳 / 提交顺序 / 声明+抽查），并写覆盖条目数
   - 单独一节「源材料存疑项」：若参考答案/源文档有笔误、歧义、省略，写出你的判定与依据（没有就写"已逐条复算，与源材料一致"）
   - 关键数值用 {{CALC_TOOL}} 复算，不要只靠心算；算式或脚本留在 {{WORK}}/audit/calc/
4. 完成后汇报：KEY 已就绪、覆盖条数、源材料存疑项数量。
5. 然后停下等我消息（阶段二我会再叫你，届时才开放 A/B）。

# 要求
- 宁可写细：这是你后面全部判决的标尺。
- 只写 {{WORK}}/audit/KEY.md，不要改别的文件。
```

## 2. 复核员 · 阶段二（交叉复核）

```text
阶段二：A、B 两套盲产成果都已冻结并通过 validate，请做交叉复核（任务 {{CR_TASK_ID}}）。

【冻结产物】
- A：{{WORK}}/{{DIR_A}}/（{{A_STAT}}）
- B：{{WORK}}/{{DIR_B}}/（{{B_STAT}}）
- 你的标尺：{{WORK}}/audit/KEY.md

【要做的事】
1. 逐条核对 {{N_ITEMS}} 条 × 2 套：条件是否丢失/篡改、结论是否正确、关键中间量是否一致、
   引用（字母/序号/编号）是否指错、计数是否对齐。**每条都要有判决，不许"未检查"**。
2. 交互/工程问题：实机走查 {{SELF_TEST_ITEMS}}；记录控制台错误、状态恢复、防作弊（改答案刷分）、
   多产物共享存储等。
3. 评分卡：先定口径（{{RUBRIC_REF}}）再打分，别用"感觉"。
4. 产出 {{WORK}}/audit/REVIEW.md：
   - 评分卡 + 骨架建议（哪一套适合做终版）
   - blocker / major / minor 清单，每条 {id, 侧, 问题, 证据, 修法}
   - **逐项取谁表**：每条 id 一行，A / B / 合并，附一句话理由（这是合并的机械指令）
   - 源材料存疑项在 A/B 中的处理：复述含混 vs 答错
5. 可选但推荐：{{WORK}}/audit/ERRATA.json（机器可读问题清单）。

【时间预算】默认：写 KEY ≤ 生产耗时的 25%，交叉复核 ≤ 40%，Δ 复核 ≤ 10%。超出时必须在报告「局限」一节声明未覆盖项，并进入 FINAL_REVIEW §6。
优先保证"逐项取谁表"和 blocker 清单准确，其余从简。
完成后把结论压成 ≤15 行汇报。
```

## 3. Lead · 合并

```text
按 audit/REVIEW.md 的逐项取谁表机械合并，逐条关闭 blocker。

要求：
1. 每条 blocker 在 MERGE_NOTES.md 里一行：编号｜修法｜关闭证据（diff 片段/断言输出）。
2. 偏离取谁表的每一处都要写理由。
3. 最终 {{VALIDATE_CMD}} 必须 0 error。
4. sha256(构建产物) == sha256(交付副本)，并把两个哈希写进 MERGE_NOTES.md。
5. 追加 ROUNDS.md 一行记录本轮。
```

## 4. 二审（第四人或复核员新轮）

```text
二审：对终版做独立复核（任务 {{FINAL_TASK_ID}}）。结论只能是 通过 / 有条件通过 / 打回。

【对象】
- 终版字节：{{DELIVER_PATH}}（sha256 前 16 位 {{HASH}}）
- 上一轮通过版本：{{PREV_HASH}}（据此判断 Δ 范围）

【必须做】
1. 复跑断言：对 REVIEW.md 的每条 blocker，**自己重新执行验证**（脚本/点击/比对），
   不接受"报告说已修"。逐条写"复现结果"。
2. Δ 复核：列出上一轮通过之后发生的**全部**改动，逐项断言（不是抽查）。
   常见 Δ 类型：内容补丁、排序/重排、文案、交互修复、构建参数。
3. 结论：0 blocker 才能写"通过"；有 major 必须写明"是否可发布"。

【边界】只写 {{WORK}}/audit/FINAL_REVIEW.md，不要改产物。
完成后 ≤10 行汇报。
```

## 5. 返工指令（Lead → 生产者 / 复核员）

```text
第 {{R}} 轮返工。门禁 G{{N}} 红，问题清单：
{{ISSUE_LIST}}   # 每条：{id, 现象, 期望, 证据}

要求：
1. 逐条修，改完给出"改动点 → 期望影响"的三行说明。
2. **整门禁复跑**（不是只跑失败项），把输出贴回来。
3. 修完仍由提出方复验；复验通过前不得进入下一阶段。
```

> 复跑整个门禁的理由：本次实战里"改选项顺序"引出了"解析字母指代错位"，再引出"第 N 项序号指代错位"——只验原失败项会漏掉这两层回归。

## 6. 提示词质量自查（派工前必看）

- [ ] 两个生产者的提示词**逐字对比过**（除目录名/id）
- [ ] 合同路径、源材料路径、输出目录都是绝对路径（子智能体可能不共享 cwd）
- [ ] 验收命令可复制粘贴直接跑
- [ ] 质量红线全是可判真假的句子
- [ ] 明确写了"不要读对方目录"
- [ ] 明确要求"主动自陈不足"
- [ ] 汇报长度有上限（防止长篇复述消耗预算）


---

## 7. 返工后的复验指令（提出方执行）

```
第 {{R}} 轮复验。上一轮我提的问题：{{ISSUE_LIST}}

请**重新执行**验证（不要看修复者的说明），逐条给：
| 编号 | 我的复现步骤 | 本轮结果 | 判定(关闭/未关闭) |

同时跑一遍整门禁：`{{GATE_CMD}}`（不是只跑失败项）。
若有新问题，按严重度追加到 REVIEW.md，并开下一轮。
```

## 8. 二审指令里的 Δ 边界

```
被审对象：{{DELIVER}} sha256={{HASH}}
上一轮通过版本：{{WORK}}/_versions/R{{PREV}}/
Δ 范围用 `node {{SKILL}}/scripts/manifest.mjs {{WORK}} --diff {{WORK}}/_versions/R{{PREV}}/MANIFEST.sha256` 确定，
逐项断言，不要凭记忆。
```
