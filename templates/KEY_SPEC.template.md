# 基线规范（KEY_SPEC）

> 复核员写 `audit/KEY.md` 的字段规范。**格式固定，因为后面要用脚本比对覆盖度。**
> 复制本文件到 `<work>/contract/KEY_SPEC.md` 并按项目改；改了就同步改 `gate.config.json` 的 `structure`。

---

## 1. 文件头（必须有）

```markdown
# 独立基线 KEY
- 生成时间：YYYY-MM-DDTHH:MM+08:00
- 独立性声明：本文件在读取 `a/`、`b/` 任何文件之前完成（三选一：时间戳 / 提交顺序 / 声明+抽查）
- 覆盖条目：N / N
- 源材料：<源文件清单>
```

三条声明缺一条，G2 直接红。

## 2. 每条目一节（格式固定）

```markdown
## <id> <标题>

| 字段 | 内容 |
|---|---|
| 核心条件 | 页大小 4 KiB；VPN 2 → PFN 9；只读 …（把数字抄全） |
| 关键中间量 | 0x2345 >> 12 = 2；2 × 4096 = 8192；8192 + 0x345 = 0x9345 |
| 最终结论 | 读成功，PA = 0x9345；写触发保护异常 |
| 易错点 | ① 把 TLB 命中当作权限通过 ② 忘记页内偏移 |
```

**"关键中间量"是必填项**：没有它，复核员无法判断"过程错但答案对"。

## 3. 机器可比对的约束

`gate.config.json` 的 `structure` 用正则在 KEY 里数行：

```json
{
  "path": "audit/KEY.md",
  "stage": "G2",
  "rowPattern": "^\\|\\s*核心条件\\s*\\|",
  "minRows": 34,
  "coverIdsFrom": "idsCoverage",
  "forbid": ["独立性声明：\\s*无"]
}
```

- `rowPattern` 命中行数 ≥ `minRows`（= 条目数）
- `coverIdsFrom` 要求每个条目 id 都有一行 `| <id> ... |`
- `forbid` 拦住"自我声明为空""待补"这类占位

## 4. 源材料存疑项（必须有这一节）

```markdown
## 源材料存疑项

| # | 位置 | 疑点 | 我的判定 | 依据 |
|---|---|---|---|---|
| P1 | 第 3 页参考答案 | 时间线漏标中途降级 | 结论不变，但考点缺失 | 逐 tick 推演 |
```

无则写：`无（已逐条复算，与源材料一致）`——**不能只写"无"**，否则无法区分"查过"与"没查"。gate 的 `structure.forbid` 会拦截裸"无"。

## 5. 数值复算要求

凡涉及计算，KEY 里必须留下**可复现的算式或脚本**（脚本放 `audit/calc/`）。心算值不算基线。

## 6. 反模式

- 只有最终答案，没有中间量 → 无法判过程
- 直接抄源材料的参考答案 → 未独立推导，标尺失效
- 出现 A/B 的原创措辞 → 独立性被污染，G2 直接红
